# Civic lists — the town's own lists of its own people

**What lives here.** The poll books, voter rolls and election returns of 1833-1835,
and the officers, jurors, petitioners and subscribers printed beside them. Four
voter lists of 1833-1835 name 346 entries between them; the residents layer holds
99 of their 215 surnames, and closing that gap is what this domain is for (T-0493,
T-0514).

**Shape: `records`.** A voter roll is a LIST, so every row is a record and not a
claim about the town — `as_read` is what the page says, `normalized` is how this
project spells it, and the two are never collapsed. One row, one `locator`, one
`reading` grade, one `confidence`. `tools/research_domains.py --check` holds the
shape; `data/research/domains.json` states it.

**Hand-authored:** `coverage.json`, everything under `claims/`, and every judgement
in `crosswalk.json` that a rule did not make. A claim is read by a person out of a
named passage, and the gate can only check that it is well formed — it cannot check
that it is true.

**Generated, and re-derived by the gate:** `text/voter_lists_1833_1835.txt` (a
byte-identical copy of the read-only deposit), `records/voter_lists_1833_1835.json`,
`voter_crosswalk.json` and this domain's rows in `crosswalk.json` — all written by
`tools/read_voter_lists.py --build` and re-derived by `--check`, which refuses a
committed file that has drifted from the text. A poll book is 345 printed rows and
the only honest reading of row 214 is what line 214 says; typing them by hand would
introduce exactly the errors `as_read` exists to exclude, and nothing downstream
could tell a typo from an 1835 spelling. `search_log.json` is written by
`tools/sweep_voter_second_sources.py --sweep`, which is a research pass and not a
gate: it reaches the network, so it is run deliberately and its result is committed.
`data/research/domains.json` is generated by `tools/research_domains.py --build` and
a hand-edit to it fails the gate.

**What the tools do NOT decide.** Which entry is which resident. `read_voter_lists.py`
proposes a match only where one resident of the surname agrees with the entry's
forenames initial for initial and no other does; everything else is a candidate or a
refusal, and every refusal is written into `crosswalk.json` with the rule that made
it. Nothing here mints or regrades a resident — T-0514 and T-0515 do that.

**Coverage.** Declare the LIST you read, by name, in `coverage.json`. An undeclared
list is not read yet, which is not a fault; a declared list nothing reaches is a
hole, and the gate says so. Declaring a list you skimmed is how the next run comes
to believe the work is done.

**Identity.** `crosswalk.json` carries the merges and the refusals, in
`../newspapers/identity.json`'s shape and under its rules: a merge needs a written
rule, the rule names BOTH spellings verbatim, and a surname-only merge is always a
refusal — these lists are full of families and a bare surname separates none of
them. A refusal is written down as carefully as a merge, because the absence of one
reads exactly like a pair nobody has looked at yet.

**This is research, not payload.** `tools/publish.sh` does not copy `data/research/`
and `tools/newspaper_corpus.py --check` asserts that nothing under it has reached
`site/chicago/4d/`. Nothing in this folder ships to a browser.
