The generator half of the wharf layer: a river-wharf mode of `pier_crib`.

Filed by the run that shipped **T-0041**. `docs/ROADMAP.md` K5 (e) asked for the docks and said
they "need a river-wharf mode of `pier_crib`". That turned out to be a BAKE reason rather than a
blocker — the renderer-side half needs no Blender and is shipped — but the generator half is still
owed and is what a BAKED town would carry: `generators/archetypes/pier_crib.py` builds the harbour
piers, and nothing builds a river wharf, so a scene assembled from GLBs alone has no docks in it.

The outline is already derived and committed (`data/wharves/river_landings.json`), so this is the
archetype and its params, reading that record rather than inventing a second set of numbers.

**NEEDS THE BAKE** — Blender, so the improve runner cannot close it.

## WITHDRAWN 2026-08-24 — measured, and the route this ticket names cannot be built

Measured before building, with `tools/measure_generator_half.py` (committed by this run; `--gate`
holds both readings). Three findings, in the order they were taken.

### 1. "Generated by rule rather than hand-placed" is already true

Nothing about the wharf layer is hand-placed. `tools/generate_river_wharves.py` derives every
landing from the committed footprints, the traced 1834 bank and the committed heightfield through
a six-clause rule, and `tools/check.sh` re-derives `data/wharves/river_landings.json` **byte for
byte** on every commit. The ticket's own body says so — *"the outline is already derived and
committed"*. What it asks for is not a rule; it is a Blender path so a town assembled from GLBs
alone carries docks. That is a different question, and it is finding 3.

### 2. The route it names — a mode of `pier_crib` — is refused by the project's own staleness hash

`generators/mesh_inputs.py` hashes an archetype's builder, `generators/build.py` and
`generators/common/*.py` into every asset's `inputs_sha256`, and `_params_doc` hashes every FIELD
and every `@property` of the resolved parameter object. So there is no edit that adds a mode
without re-staling committed meshes, and `tools/validate.py --all` — the merge gate — fails on a
stale asset. Measured over the 348 committed, input-tracked assets:

| edit site | re-stales |
|---|---|
| `generators/common/*.py` | **348** — every committed mesh |
| `generators/build.py` (the import + the `ARCHETYPES` entry) | **346** — every structure in the town |
| `generators/archetypes/pier_crib.py` (the builder) | **2** — both harbour piers |
| a new field or property on `PierCribParams` | **2** — the same two, through the resolved params |

Wiring ANY new archetype into the bake costs 346 re-staled meshes, because `build.py` is where the
archetype table lives and `build.py` is in every structure's hash. That is not a defect of this
ticket — `generators/common/phases.py`'s own docstring argues the hash SHOULD be that wide, and
T-0161 paid the price knowingly with a full rebake. It is a statement about who can do this work:
**`AGENTS.md` puts Blender off the improve runner**, so the branch that adds the mode cannot make
its own gate green, and the ticket's `needs_bake: true` is right about the flag and wrong about the
size — this is not one run's work behind a bake, it is a full rebake of the town.

### 3. And it is nine layers' debt, not the wharf's

The wharf is one of **nine** data layers drawn at load from committed JSON rather than from a
baked GLB — boats, enclosures, fauna, flora, frontage, residents, signage, wharves, yard — and
**none of the nine has a generator**. `docs/ROADMAP.md` K5 asks for "the generator half" of three
of the others in almost the same words. Building one of the nine, by a route that re-stales the
whole town, would leave eight unbuilt and the general question still unasked: **should a baked
town carry the derived layers at all, or is "derived at load from committed data" the answer for
them?** Every one of the nine has an argument written into its own record for why it is not baked
— *"a deck on cribs is a box on boxes standing on ground and water this project already draws"* —
and the project has made that argument four times without ever deciding it once.

### So

Withdrawn as a route, not as a subject. The subject is refiled whole, with these numbers, as the
successor ticket named in this ticket's `blocked_on` line — one decision about nine layers, taken
by a session that can run the bake, rather than a fragment nobody can ship. The visible half of
this parcel shipped in the same PR as **T-0058**: the decks a visitor can now walk out along.

**Acceptance (met):** the reading is committed as a tool rather than asserted — `python3
tools/measure_generator_half.py` prints both tables, `--gate` fails if either moves off the figures
written into the tool beside them.
